# VisionEdge 2.4.0 使用手冊

繁體中文 · 操作員與設定工程師 · 2026-09-25

> 適用於有人員監看的現場試運轉。尚未完成現場真機、誤判率與長時間運作驗收，不應只憑本版軟體判定作為唯一出貨放行依據。本手冊描述已實作功能，不包含旋轉校正或 APL。

## 1. 第一次使用：先樣板，再規則，最後才是流程

VisionEdge 2.4.0 以 tm_app 的取像與標記方式為主。一般外觀檢查不必建立 SOP；需要依序放料時，才啟用 Flow Studio 的順序檢測。

| 入口 | 工作 | 下一步 |
| --- | --- | --- |
| 即時檢測 → 設定 | 選相機驅動、解析度、來源、產品及檢測速度 | 先確認影像正確且持續更新 |
| 取像與樣板 → 左側產品 | 建立料號或選擇既有產品 | 確認正在編輯哪個產品 |
| 取像與樣板 → 相機取像 | 預覽、讀取 Qualcomm 支援的控制並調整 | 固定光線與相機後再擷取 |
| 擷取樣板畫面 | 擷取、放大、畫框及儲存獨立 Label | 框選草稿必須按「儲存 Label」 |
| 樣板庫 | 個別改名稱、門檻、位置容許值、查看引用 | 儲存該列，試跑，再套用 |
| 套用檢查 | 沒有規則時建立基本 ALL 檢查 | 回即時頁做良品與異常測試 |
| 規則／Flow Studio | 由已存 Label 組成檢查組，必要時啟用順序 | 儲存並套用後驗證完整流程 |

三種「保存」不要混淆：釘選畫面只保留本次工作的取樣畫面；「儲存 Label」寫入樣板庫；「套用檢查／儲存並套用」才把設定交給正式檢測。尚未套用的變更不能當作目前執行設定。

新工程師先完成第 2、3、5 章的單張案例，再學第 4、6 章的規則與包裝。操作員日常只需選產品、依提示放料及處理異常。

## 2. 從空白到相機可用：設備設定逐項操作

### 第一次啟動的順序

1. 請設備管理者提供已啟動服務的網址，並確認程式版本為 2.4.0。本手冊不假設新電腦已安裝相機驅動及 Python 依賴。
2. 進「設定」，先把「檢測產品」選成「不選產品，僅相機預覽」。先確認影像可用，再設定檢測。
3. 依下表選擇驅動、來源、解析度及方向；按「套用設定」。若相機尚未啟動，回「即時檢測」按「啟動相機」。
4. 確認畫面不是黑畫面、不是舊影像，而且方向正確；移動手邊物品確認畫面會更新。
5. 固定相機、光源及治具。完成後再擷取樣板；事後變更解析度、方向、鏡頭校正或相機位置，需要重新驗證樣板位置。

| 欄位／所在區塊 | 怎麼選 | 注意事項 |
| --- | --- | --- |
| 相機／相機區 | 設備預設相機通常為 0 | 這不是 USB 相機來源索引的通用替代；PC 來源在進階設定 |
| 解析度 | 畫面選項為 1920×1080、3840×2160；先確認設備支援 | 更高解析度不保證更準，會增加負荷；先驗證實際速度 |
| 畫面方向 | 選 0° 或 180° 使畫面正向 | 是固定翻轉，不會自動把歪斜箱子轉正 |
| 鏡頭變形校正 | 沿用設備已驗證設定 | 屬於設備能力，不是各種 OpenCV 相機都能套用的通用校正 |
| 檢測產品／產品與檢測 | 建好產品後選其料號 | 選「不選產品」只有預覽，不能做有效產品判定 |
| 檢測速度 | 初次測試選標準每秒 5 次；也可選 2 或 10 次 | 是目標頻率；以即時頁的實際檢測更新率為準 |
| 錄影品質 | 自動為起點；另有 8／16／24 Mbps | 碼率影響影片大小及品質，不是樣板判定門檻 |
| 保留空間 | 5／10／20 GB，預設 10 GB | 不是歷史資料容量上限；不足時會限制寫入與錄影，不會自動替你整理所有履歷 |
| 相機驅動／進階相機設定 | 正式 Qualcomm 設備通常 Auto；PC 測試選 OpenCV fallback | QTI 是設備驅動，不能把一般 PC 當成 QTI 設備 |
| 測試影像來源／進階設定 | OpenCV 下輸入 0 使用第一個可用攝影機，或輸入伺服器可讀的影片完整路徑 | 路徑在執行 VisionEdge 的主機上，不一定是瀏覽器所在電腦；不要把網址或路徑填入檢測產品 |
| 放棄變更 | 恢復到已儲存的設備設定 | 不代表撤銷已儲存的模板或產品 |

PC 測試例：相機驅動選 OpenCV fallback，來源填 `0`，先用預覽確認攝影機。要重播影片則填例如 `D:/test/packing_trial.mp4`，檔案必須真的存在於伺服器；套用後啟動相機。循環影片開頭應包含清空工作區，否則包裝模式可能一直等清空。影片測試不能取代實際相機節拍驗收。

「在取像與樣板載入影片」是取樣建模板；「在設備設定把影片當來源」才是讓執行端持續用影片進行檢測，兩者不同。


### Qualcomm 相機的取像調整（2.4.0）

1. 進「取像與樣板」，左側按「啟動／查看即時預覽」，等影像穩定。按「讀取相機狀態」可重新查詢目前設備能力。
2. 展開「Qualcomm 取像設定」。若顯示「目前不是 QTI 相機」或「尚未確認設備支援」，不要把停用的控制當成已生效；先確認驅動和設備。
3. 初次使用保留「相容模式」：只寫入白平衡，其他項目停用。「不寫入控制」保留驅動的初始行為；「手動模式」才可改設備回報支援的項目。
4. 想讓畫面更亮或更暗，先小幅試曝光補償。控制範圍以實際顯示為準。模式類欄位若韌體提供名稱會以選單呈現；不要把數字猜成曝光時間或焦距。
5. 按「儲存並重新啟動相機」。未存框選會提示是否放棄；進行中的工件／箱子或錄影會阻止變更，先結束或中止並停止錄影。
6. 等相機恢復，確認狀態及實際影像。讀回成功只代表驅動接受的屬性值一致，還需用畫面確認亮度與色彩。調整後重新擷取並驗證樣板。

| 控制 | 軟體允許範圍 | 使用方式 |
| --- | --- | --- |
| 白平衡模式 | 0–10，仍須設備支援該值 | 相容模式只調此項；有韌體選項名稱時依名稱選 |
| 曝光補償 | -12–12 | 小幅增減，觀察過曝、反光與陰影；不是曝光微秒數 |
| ISO 模式 | 0–8 | 依設備模式；選手動值前確認相容的 ISO 模式 |
| 手動 ISO | 100–3200 | 是否生效仍取決於設備及 ISO 模式，先看雜訊與亮度 |
| 抗閃爍模式 | 0–3 | 依韌體選項及現場光源調整，確認條紋是否改善 |
| 對比 | 1–10 | 調整明暗差異，避免細節消失 |
| 飽和度 | 0–10 | 調整色彩；目前樣板比對主要使用灰階，不能只依顏色假設可區分 |
| 銳利度 | 0–6 | 影像銳化不是光學對焦，不能修復嚴重失焦 |

實際欄位會與驅動回報的範圍取交集。不支援、寫入失敗或讀回不一致會顯示錯誤。若手動模式使相機無法啟動，改回相容模式或不寫入控制並重新啟動，再檢查設備狀態。

本版沒有通用光學焦距／對焦滑桿。焦距與自動對焦需要相機模組及韌體專屬介面，尚未在實機驗證；不要把標記區 100%／200% 當作鏡頭調焦。相機設定由取樣與生產共用，並非每個 Label 的獨立曝光設定。

## 3. 抓圖、放大、標記與個別 Label 設定

### 從相機建立第一個 Label

1. 進「取像與樣板」。左側新增產品輸入 `DEMO-LABEL`，按「建立」；確認檢測產品已選到此料號。
2. 把標準良品放在正確位置。需要先看即時畫面時，按「啟動／查看即時預覽」。確認對焦及照明後按「從相機擷取」，取得固定影像。
3. 在新 Label 名稱填 `LABEL_OK_01`，類型選 OK 候選。新 Label 預設門檻可先用 `0.80` 試驗，這只影響接下來的新框，不會修改已存 Label。
4. 影像太小時按「100%」或「200%」。100% 對應原圖像素；200% 只是放大顯示，不增加相機細節。也可用 ＋／− 或 Ctrl＋滑鼠滾輪。
5. 用捲軸找目標，或啟用「拖曳平移」後用左鍵移動畫面。要畫框前再關閉平移。也可直接用中鍵拖曳，左鍵保留框選用途。
6. 用左鍵從目標左上拖到右下。選可區別良品與異常的文字、圖形或邊緣，不要只選純色背景。避免把手或暫時反光框入。
7. 框選下方出現草稿列。直接改該列的名稱、門檻與位置容許偏移，例如 `LABEL_OK_01`、`0.85`、`8`。按該列「儲存 Label」。畫錯則刪除草稿列重畫。
8. 草稿列消失、下方樣板庫多一列才代表保存成功。這個動作不會建立流程步驟，不需要指派到 Step。
9. 重複擷取其他合格外觀或已知異常。NG 樣板要使用確實能區別錯誤外觀的框；「未符合 OK」不等於「符合某個 NG 樣板」。

### 每個 Label 的欄位

| 欄位 | 修改方式與意義 |
| --- | --- |
| Label 名稱 | 樣板庫該列直接輸入。使用用途和位置，例如 A_左槽、SEAL_OK。名稱可自行定義，不必使用系統固定名稱。 |
| 比對門檻 | 每列獨立，範圍 0–1。分數大於等於門檻才命中；0 是合法值但幾乎失去篩選作用，不適合作量產起點。 |
| 位置容許偏移 | 以原圖像素計算，0 表示全圖搜尋；大於 0 才限制原框附近的搜尋範圍。例：8 表示原位置周圍允許約 8 像素搜尋。不是角度，也不是物件整體必須落入框的判定。 |
| 樣板類型 | OK／NG／一般是選用提示。既有規則實際的 OK／NG 角色仍在規則內設定，改提示不會把既有 OK 角色反轉。 |
| 引用規則 | 顯示產品編號及使用此 Label 的規則名稱。修改名稱、門檻或 margin 會同步修改引用副本，其他引用產品也要重新套用。 |
| 儲存 Label | 只保存該列。其他列尚未保存的編輯會保留，但仍須各自儲存。 |
| 刪除 | 引用中的 Label 不可刪除；先移除規則與包裝條件的引用。刪除前確認不是其他產品仍需要的樣板。 |

放大後保存的 x/y/w/h 仍是原圖像素，與畫面縮放比例無關。包裝模式會改用包裝設定中的統一位置容許值，因此 Label 試跑和包裝模式必須分別驗證。

### 修改已保存的 Label

1. 在樣板庫找到該列，改名稱、門檻或位置容許值，按「儲存 Label」。有引用時會提示同步影響。
2. 若另一頁或另一位工程師已修改同一 Label，系統會拒絕用舊版本覆蓋。先記下未存內容，再重新載入核對後修改。
3. 正在檢測工件、包裝循環或錄影時，先完成或中止工件並停止錄影，再調整引用中的 Label。
4. 改 ROI 或樣板照片：重新擷取、以新名稱儲存新 Label，在規則中選入新 Label 並移除舊引用，儲存並套用後重測。目前樣板庫不提供原框直接拉角重裁。

切換產品、離開頁面或重新載入時，未保存的編輯會提示確認。相機重新擷取可能更換工作影像；先保存重要草稿。釘選工作畫面不是持久備份。

### 試跑與套用

先保存所有草稿和列編輯，再按「試跑已儲存的 Label」。表格顯示每個 Label 的分數、門檻及是否命中；它使用目前相機畫面，不是剛剛釘選的舊畫面。試跑不推進 SOP，也不新增生產履歷。NG Label 的 ✓ 代表找到已知異常，絕不是產品合格。

沒有規則的產品按「套用檢查」，確認後會建立基本 ALL 組：全部 OK Label 都必須命中，任一 NG 命中則否決，一般 Label 不自動加入，SOP 保持關閉。至少需要一個 OK Label。若已有規則，套用只使用既有規則；新存 Label 不會自動加入，應先到 Flow Studio 確認引用。

載入影片取樣：選檔 → 播放或拖時間軸 → 暫停／擷取畫面 → 填名稱與類型 → 放大框選 → 儲存 Label。影片播放中不可畫框。要讓演算法連續吃影片，應到設備設定把影片設成來源，不能只在標記區載入影片。

## 4. 規則與所有進階流程欄位怎麼設定

### 先分清三層條件

| 層次 | 例子 | 正確選法 |
| --- | --- | --- |
| 一個組內的替代外觀 | 同一標籤有 A、B 兩種合法版本 | 同組放兩個 OK，選任一 OK 符合（ANY） |
| 一個組內同時必須存在 | 左右兩顆螺絲都要看得到 | 同組放左、右樣板，選全部 OK 符合（ALL）；必須確保兩個樣板不會都匹配同一顆螺絲 |
| 不同組的整張判定 | 標籤組及封條組都通過 | 「整張畫面怎樣才算合格」選全部組（ALL） |
| 時間順序 | 先放 A，再放 B | 建兩個步驟、啟用依序檢測；不是選組間 ANY |

同外觀物品的多個模板不等於可靠計數；位置不受限制時，可能都找到同一個目標。一般流程頁新增模板預設 search_margin 為 0，且未提供逐模板 margin 輸入，因此不要把一般模式描述成保證固定位置檢查。包裝模式會用「位置容許偏移」統一限制觸發和步驟模板。

| 左側「進階流程設定」 | 作用 | 初次依序作業設定 |
| --- | --- | --- |
| 站別名稱 | 顯示及設定中的站別識別 | 例如 PACK-01；不是新建產品 |
| 依步驟順序檢測 | 啟用 SOP 時序 | 單張案例關；包裝案例開，包裝啟用時會強制開 |
| 嚴格依序／跳步警報 | 後面步驟先達條件時提出異常 | 依序作業開；包裝強制開 |
| 步驟逾時警報 | 允許依步驟逾時設定產生警報 | 需要監控節拍才開，還要設定每步逾時秒數 |
| 警報鎖定至人工確認 | 警報不因下一張影像改善就自動消失 | 開；包裝強制開 |
| 網頁警告聲 | 網頁提示音 | 依現場需要開；瀏覽器需先有使用者點擊才能允許音訊 |
| 完成後重置 | 人工重置或完成後延遲重置 | 新手先人工；延遲模式可能讓未取走的工件再次進入流程，包裝不能用它代替換箱 |
| 完成後延遲秒數 | 僅延遲自動重置模式使用 | 人工／包裝模式不用調 |
| 三色燈輸出、綠／黃／紅 DO | 保留的硬體欄位 | 本版不提供可用的硬體輸出，不要把它當成已接妥警示燈 |

每張步驟卡展開「進階判定條件」可設定下列項目；標準新步驟預設啟用、必要、連續 2 次、保持 400 ms、逾時 0。

| 步驟欄位 | 意義／範圍 | 實例與常見錯誤 |
| --- | --- | --- |
| 啟用 | 是否參與該流程 | 必查項目不要停用以消除警報 |
| 必要 | 是否為 SOP 必須完成的步驟 | A、B 都必放就都選必要；這不等於單張模式免除該組 |
| 組內 ANY／ALL | 多張 OK 樣板的關係 | 替代外觀用 ANY；同畫面全部必要用 ALL |
| 連續命中幀 | 1–120 次連續推論命中 | 2 是起點，不是相機擷取兩幀即通過 |
| 持續時間 ms | 0–600000 ms；與命中次數同時滿足 | 400 ms 是 0.4 秒；實際檢測慢時完成時間也變長 |
| 逾時秒數 | 0–86400 秒；0 不設此步逾時 | 先量實際操作時間再設定，如練習用 10 秒，不是通用標準 |
| 允許提前 | 一般流程可允許步驟提前 | 包裝會強制依序並停用這個選項 |
| 完成後鎖定 | 完成後保持 DONE 或允許回復未完成 | 先放 A 後遮住 A 的流程通常保持鎖定；最後是否需可見由包裝最終勾選另外決定 |
| 漏步警報 | 該預期步驟被跳過時是否報警 | 必查步驟保持啟用；搭配全域嚴格依序 |
| 最後仍須可見 | 包裝最後再次檢查此步的物品 | A、B 最後都看得到就都勾，不要只為通過而取消 |

用 ↑／↓ 或拖曳把手調順序；可用複製建立相近步驟，但複製後需更名、換成正確位置的模板，避免兩步檢查同一個位置。新增的空白步驟也需要加入 OK 模板才能套用。

## 5. 使用案例：不用 SOP 的標籤與封條檢查

目標：產品必須同時有正確標籤及封條，遇到已知錯標立即不合格。

1. 建立 `PACK-LABEL`。放正確標籤和封條的樣品，擷取固定畫面。
2. 分別框標籤和封條，儲存 `LABEL_OK`、`SEAL_OK`，類型都用 OK；分別設定門檻。不要把兩物件與大片背景合成一個大框。
3. 需要限制位置時，各列位置容許值設定大於 0，例如 8 像素。相機或工件定位較不穩，先改善治具再決定數值。
4. 放已知錯標，擷取並保存 `LABEL_WRONG`，類型 NG。不要只框所有標籤都相同的白底。
5. 依次放良品、缺標、缺封條、錯標和錯位置，按 Label 試跑，記錄各分數。確認 NG 樣板不會在良品上命中。
6. 按「套用檢查」建立基本檢查，確認對話中的 ALL 與 NG 優先規則。不用開啟依序檢測。
7. 回即時檢測，用相同測試組按「拍照判定」，核對結果及履歷。測試後「結束此件」再換件。

若標籤有 A、B 兩種合法外觀，基本 ALL 不適合把它們全放同一組。新增 B 樣板後進「規則／Flow Studio」，將標籤 A/B 放在「標籤組」並選任一 OK（ANY），封條單獨一組；整張畫面選全部檢查組通過（ALL）。每個組都需有 OK 樣板，錯標 NG 放入相關組。

調門檻例：某 Label 良品最低分 0.92、錯品最高 0.71，可先試 0.85，再用未參與調整的樣本測試；這是假設示例，不是保證值。分數重疊時應改框、改善照明或定位，而非不斷降低門檻。調整後按該列儲存，再套用正式檢查。

## 6. 使用案例：A 放位置 1、B 放位置 2，自動換箱

目標：空台 → 空箱就位 → A 入左槽 → B 入右槽 → 齊套 → 取走結算。先固定相機、箱子方向與兩個槽位。此版不會自動校正箱子的旋轉。

### 先建立五個獨立 Label

1. 新建 `BOX-AB`。工作區清空後擷取，框整個放箱區，保存 `AREA_CLEAR`，類型一般。
2. 放空箱再擷取，框箱內空間，保存 `BOX_EMPTY`，類型一般；放入物品後這張應不再命中。
3. 同張空箱畫面框放料後仍露出的箱緣或固定特色，保存 `BOX_PRESENT`，類型一般；空台或箱子錯位時不能命中。
4. 把 A 放左槽，擷取並保存 `A_LEFT`，類型 OK，框住能識別 A 的部分與正確位置。
5. 把 B 放右槽，擷取並保存 `B_RIGHT`，類型 OK。每個 Label 先分別測分數與位置容許值。

### 再編排流程

1. 按「規則／Flow Studio」。新增兩個檢查組，名稱設為「A 放左槽」「B 放右槽」。在各組按「＋ 選擇 OK / NG 樣板」，分別選 A_LEFT、B_RIGHT 為 OK，按完成。
2. 開「依步驟順序檢測」。保持 A 在前、B 在後；使用卡片上下箭頭或拖拉把手調整。練習可先用連續命中 2 次、保持 400 ms；實際值需依工站速度測試。
3. 開「用影像自動開始與換箱」，選「箱子或托盤會取走」。下拉選擇清空 AREA_CLEAR、空箱 BOX_EMPTY、定位 BOX_PRESENT。三者只作循環條件，不放入物品檢查組。
4. 包裝位置容許值先試 8 像素、穩定 0.8 秒、齊套 1 秒；這些是起點。包裝模式的 margin 會用於循環條件及流程樣板，不沿用各 Label 試跑的獨立 margin。
5. A、B 在完成時都看得到，兩步都勾「完成時仍須看得到這一步的物品」。儲存並套用，回即時頁驗證。

### 按這個順序驗收

| 操作 | 預期 |
| --- | --- |
| 開機時桌上已有箱子 | 先要求清空，不承接不明進度 |
| 清空工作區 | 穩定後等待空箱 |
| 放空箱並保持定位可見 | 開始一箱，提示先放 A |
| A 放左槽 | A 步完成；錯放右槽不能完成 |
| B 放右槽且 A 還在 | B 完成，齊套穩定後提示取走 |
| 完整取走並看到空台 | 結算一次合格，等待下一箱 |
| 同一箱一直留在畫面 | 不應反覆增加箱數 |

必測異常：B 先放、只放 A 就取走、缺件、錯位置、NG 命中、手擋定位、最後取掉 A、斷流或停相機。遮擋不等於取走，先確認提示再處理；中途中斷後必須清空重來。

固定治具改選「固定治具，只取走物品」：使用空治具內部作清空、固定治具特徵作定位，不用空箱 Label。仍要依序放 A/B，取走物品並清空後才換件。

若 A 最後會被包材蓋住，可只取消 A 的最後可見勾選，B 保留。這只證明 A 曾放入，不能證明遮蔽後仍在箱內；需要這項保證就調整視角或作業程序。

## 7. 先選對操作方式

| 方式 | 適用情況 | 如何開始 | 紀錄方式 |
| --- | --- | --- | --- |
| 單張拍照判定 | 檢查當下外觀或固定畫面的條件 | 滑鼠按「拍照判定」；或序號欄按 Enter | 每次判定保存原圖、結果與明細 |
| 連續檢測／SOP | 觀察辨識效果或依序完成步驟 | 啟動相機並套用產品 | 即時更新；不代表每幀都有拍照履歷 |
| 自動包裝循環 | 依序放料、完成後取走換箱 | 先清空工作區，再放空箱 | 保存開始、步驟、異常、齊套與取走等事件 |

「儲存畫面」只存圖片，不等於「拍照判定」。單張合格也不等於整個 SOP 完成。自動包裝啟用時，手動拍照判定會停用。

## 8. 每班開始前

1. 確認相機、照明與工位固定，箱子方向符合建立樣板時的方向。
2. 用瀏覽器開啟現場工程師提供的設備網址。系統不需登入；頂部語言選單可選繁體中文或 Español。
3. 確認目前產品／料號正確，按「啟動相機」。
4. 確認畫面持續更新、檢測已就緒、儲存空間正常，且沒有「設定已更新、尚未套用」提示。
5. 用已知良品與已知異常品確認判定；包裝模式另做一次完整清空、放料與取走循環。

若畫面凍結、離線或檢測未就緒，先停止使用判定結果，通知工程師排除問題。

## 9. 操作員：單張檢查

1. 確認未啟用自動包裝，把工件放在標準位置。
2. 需要追蹤序號時，在「產品序號」輸入或掃碼。若啟用必填序號，未輸入不能判定。
3. 按「拍照判定」，等待判定與保存完成。序號欄按 Enter 也會觸發。
4. 查看「合格」「不合格」或「待確認」。待確認不可當成合格。
5. 要調整同一件工件時，按「重新拍照判定」。每次重拍保留獨立紀錄，序號仍鎖定。
6. 完成後按「結束此件」，再處理下一件。結束此件是關閉紀錄，不會把不合格改成合格。

先排除問題再重拍，不要只降低門檻使異常品通過。

## 10. 操作員：自動包裝

正常順序：**清空 → 空箱就位 → 放入 A → 放入 B → 齊套確認 → 取走 → 下一箱**。

| 畫面提示 | 要做什麼 |
| --- | --- |
| 請先清空工作區 | 移走箱子與物品，讓清空區域完整可見 |
| 等待下一箱 | 放入空箱，保持定位特徵可見；等到提示依序放料再開始 |
| 依序放入物品 | 按畫面指定步驟放料，等待確認後再做下一步 |
| 等待確認／定位特徵不明 | 移開手或遮擋，確認箱子回到標準位置 |
| 齊套確認完成，請取走 | 取走整箱並讓工作區清空；此時才會結算本箱合格紀錄 |
| 請處理檢測異常 | 排除缺件、NG、錯序等問題，再使用異常處理選項 |

固定治具模式不需要放空箱；清空後，辨識到物品及定位特徵才開始。仍必須依步驟順序放料。

提前取走會記為「未完成即取走」。同一箱留在畫面中不會反覆計數。停止相機、斷流或中止後，必須重新清空；不會自動承接上次進度。

### 處理異常

- 可以繼續同一箱：先處理實際問題，再按「異常處理／已排除問題，繼續檢測」。確認警報不等於判定合格，系統仍會檢查條件。
- 無法確認本箱正確：使用「中止此箱」，將本箱分流人工確認，再清空工作區重來。
- 保存失敗或儲存不足：停止作業並通知工程師；不要把未保存的結果當成有效履歷。

## 11. 工程師：管理規則與變更交接

1. 樣板相關修改統一在「取像與樣板」處理，完成後再進入「規則／Flow Studio」。
2. 每個檢查組至少選一個 OK 樣板。ANY 用於替代合法外觀；ALL 用於同畫面需要同時出現的條件。任一啟用組的 NG 命中優先否決。
3. 不需要先後順序時保持依步驟順序檢測關閉。需要包裝順序再開，檢查必要步驟、連續命中、保持、逾時與最後可見條件。
4. 從組內按 × 是移除引用，不是刪除樣板庫；可重用同一 Label，但修改它會影響各引用產品。
5. 「完成」只關閉選樣視窗，最後還要「儲存並套用」。如果只儲存成功、套用失敗，先看錯誤訊息處理，不能宣稱新版設定已在生產。
6. 每次改版留下：產品與站別、相機解析度和取像設定、Label 用途與門檻、margin、規則 ANY/ALL、SOP 時間、最後可見條件、良品與異常驗證結果及備份位置。

替換照片／ROI 時用新 Label 建立可追查的版本，更新所有必要引用後再考慮刪舊 Label。上線前確認其他產品是否引用同一樣板。

## 12. 工程師：設定自動包裝

啟用「用影像自動開始與換箱」，選箱子／托盤或固定治具模式。先在「取像與樣板」保存清空、空箱與定位 Label，再回 Flow Studio 由三個下拉選單選擇；不必把循環樣板加入物品檢查組。

| 條件 | 應框選的內容 | 必須測試 |
| --- | --- | --- |
| 工作區清空 | 整個放箱區或治具內部 | 有箱子／物品時不能仍判成清空 |
| 空箱已就位 | 空箱內部；固定治具模式不使用 | 加入物品後應不再符合 |
| 定位特徵 | 放料後仍看得到的箱緣或治具固定特徵 | 空台、遮擋、錯位時不能誤認為箱子有效就位 |

循環條件需選不同樣板。避免只框一小塊放料前後都不變的背景；若清空和定位同時命中，系統可能停在等待狀態。

每一步的「完成時仍須看得到這一步的物品」決定最後齊套檢查。通常應勾選所有最後可見的物品。會被後續包材蓋住的早期物品可取消，但至少保留一個最後確認步驟。取消後只能證明該步驟先前曾通過，不能證明物品後來仍在箱內。

| 參數 | 範圍／預設 | 說明 |
| --- | --- | --- |
| 條件穩定秒數 | 0.3–10 秒／0.8 秒 | 開始與清空條件需要持續成立，且至少三次觀察 |
| 齊套確認秒數 | 0.3–10 秒／1 秒 | 最後條件持續成立後提示取走，且至少三次觀察 |
| 位置容許偏移 | 1–100 像素／8 像素 | 限制樣板搜尋位置；不是旋轉容許角度或物件完整落框判斷 |
| 檢測更新率 | 包裝至少每秒 2 次／預設 5 次 | 設定值不是實際效能保證；觀察設備實際更新率 |

包裝模式強制依序、鎖定警報，並關閉延遲自動重置。進行中的箱子禁止修改相關設定；先完成或中止，停止錄影後再變更。

## 13. 履歷、照片與錄影

在「檢測履歷」上方查看自動包裝紀錄，按「查看步驟證據」開啟原圖、結果與明細。下方為手動拍照履歷，可搜尋序號或紀錄編號。自動包裝使用系統箱號，尚未整合手動模式的 SN 掃碼鎖定。

「等待取走」不是已結算合格；必須看到取走後的合格紀錄。「未完成即取走」與「已中止」都不能當成合格。

照片與錄影頁可查看、下載與管理媒體。錄影先停止並完成儲存，才能使用完成的影片。錄影期間不可直接變更相機／流程設定。事件影像與照片／錄影分開保存，刪除照片不等於清理包裝資料庫。

## 14. 工程師：測試與 polling

- 只測辨識效果：啟動相機，調整「檢測更新率」，觀察連續判定。
- 讀取結果：輪詢 `GET /api/edge/status`；讀取不會新增判定。網頁約每次回應後 800 ms 再讀。檢查 `inference_ready`、`definition_pending` 與 `packaging`，不可只看上一個合格字樣。
- 建立單張判定：`POST /api/edge/inspection`，JSON 包含 `action: "capture"`、新 UUID 格式的 `request_id`、`sn`。先用 GET 同一路徑取得狀態；同一件重拍沿用其 `cycle_id` 與序號。網路重試沿用原 request_id，真正新的判定才換新 UUID。
- 結束手動工件：同一路徑 POST `action: "close"` 和目前 `cycle_id`。新件需先結束舊件。自動包裝模式拒絕 capture。
- UI 尚無「每 N 秒新增拍照履歷」開關，也沒有專用 PLC／GPIO 觸發或正式設備互鎖接口。

## 15. 異常排查與維護

| 問題 | 優先處理 |
| --- | --- |
| 相機未就緒／無影像 | 檢查連線、來源設定及相機是否被其他程序占用 |
| 一直等待清空／空箱 | 確認對應樣板、方向、照明、位置與三個條件沒有衝突 |
| 物品在場卻不通過 | 檢查位置、旋轉、遮擋、樣板品質；先看分數再調門檻 |
| 每步完成但不能取走 | 檢查最後可見物品、NG 與尚未處理的警報 |
| 相機中斷後重新開始 | 分流原工件，清空後重新檢測；原進度不承接 |
| 磁碟不足／保存錯誤 | 暫停使用，備份、確認容量與寫入權限，由工程師處理 |

停止錄影及服務後備份整個 `db/`、`uploads/`、`runtime_data/`、`config/edge.ini` 與設備憑證。手動履歷位於 `runtime_data/inspection_history.sqlite3`；包裝履歷位於 `runtime_data/edge/packaging_history.sqlite3`。不要在服務寫入中只複製單一 SQLite 檔案。

兩類履歷會持續增加；目前沒有完整的履歷自動保留期限／輪替管理。需安排容量監控、備份及還原演練，不能假設媒體清理會清掉履歷。

升級時保留現場資料、設定與憑證，勿用範例覆蓋。若由工程師直接啟動，入口為 `python visionedge_server.py`，需既有依賴和有效設備設定；操作員沿用現場設備啟動方式。

## 16. 正式上線前驗收

目前判定：可安排受監看的試運轉；正式量產放行仍待下列現場驗收。

- 每個產品以獨立測試影像及實物驗證良品、缺件、錯件、錯位、NG、跳步、提前取走、反光和遮擋。事先訂定可接受誤判／漏判率並記錄結果。
- 驗證完整換箱、同箱停留不重複計數、重啟須清空、相機斷線與儲存不足不誤放行。
- 在目標解析度、實際相機／QTI、錄影與節拍下連續運行完整班次；再依現場需求延長測試。
- 驗證斷電恢復、時間正確、備份可還原、履歷可讀取，以及容量維護責任。
- 系統免登入，能連到設備的人可能操作設定與資料；部署在受控產線網路，由現場管理存取。

本版已驗證：13 組測試腳本通過，包括 Label 引用同步、QTI 控制模擬、13 項循環狀態測試及合成影像整合。另有一支舊 WebSocket 端到端腳本因未安裝 websocket-client 而跳過。瀏覽器已實際操作抓圖、放大、儲存／修改 Label、試跑及套用。Qualcomm 實機、光學對焦及現場節拍仍待設備驗收。

已知邊界：不自動校正旋轉、不是通用物件／手部辨識，遮蔽後無法證明箱內內容未被改動。齊套後若被遮擋再整箱取走，系統可能依先前齊套確認結算；要求防止這類操作時，需要額外可見性控制或人工確認。定位特徵不清楚時不可把畫面停住理解成已通過。
